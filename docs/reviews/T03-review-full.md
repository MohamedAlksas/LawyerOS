## Standards

Independent report, lightly formatted; four additional findings, highest **P1**:

1. **P1 — Provisioning accepts an unusable password.** `src/modules/identity/provisioning.ts:87` validates only the minimum length. A 129-character password is persisted, TOTP confirmation completes, and bootstrap closes permanently; pinned Better Auth rejects subsequent login because its maximum is 128 (`context/create-context.mjs:187`, `api/routes/sign-in.mjs:316`). This violates ARCHITECTURE section 1's equivalent server input constraints and PRD FR-01's usable provisioned account. Share provider-compatible validation before reservation and test both boundary lengths through actual login.
2. **P2 — Ambient search path redirects committed baseline DDL.** `src/cli/baseline-identity.ts:522` leaves PostgreSQL options ambient; lines 623–624 execute unqualified SQL and commit before verification. With `PGOPTIONS=-c search_path=staging,public`, tables land in staging, then public verification fails. This contradicts DEPENDENCIES section 6's public-schema/routing guarantees. Enforce the intended schema before mutation and qualify catalog/history references. Parent independently reproduced findings 1/2; reviewer performed source inspection only.
3. **P2 — Expected recovery failures lose Arabic guidance in production.** `actions.ts:48` lets AuthenticationError escape a Server Action; `security-client.tsx:101` displays err.message. Pinned Next production transport replaces thrown messages with a generic error, concealing wrong-password/lockout guidance. ARCHITECTURE section 4 requires clear codes and Arabic messages; bundled Next guidance requires expected failures as returned values. Return a typed sanitized error and cover the production browser journey.
4. **P2 — Failed logout appears completed.** `security-client.tsx:255–258` redirects after both resolved provider errors and exceptions. Failed/offline sign-out can leave the session usable while presenting login. This violates GEMINI's “No fake success” and T03's logout requirement. Show a retryable Arabic failure and navigate after confirmation.

Existing round-8 findings remain separately acknowledged: incomplete schema equivalence, ambiguous TLS query handling and current-provider HTTPS fixture configuration. No heuristic-only smell was asserted. The reviewer did not claim runtime execution.

## Spec

Independent report, lightly formatted; four additional findings, highest **P1**:

1. **P1 — Recovery policy is bypassable through the provider.** Rounds 1/2 R09 require “Route recovery changes through the Identity Interface” and a persistent bound across concurrent requests/processes. `src/app/api/auth/[...all]/route.ts:142` forwards `/two-factor/generate-backup-codes` directly. Pinned provider backup-code generation verifies password but ignores the persistent lockedUntil enforced by `recovery-codes.ts:55`. Parent PostgreSQL probe confirms generation during that lock. The provider's separate rate limiter is not the required persistent guarantee; do not call the endpoint completely unthrottled.
2. **P1 — Provisioning accepts credentials that cannot log in.** “Secure owner provisioning” and password login are T03 requirements. Provisioning checks only minimum password length; provider defaults/enforces maximum 128. Parent confirmed password129 permanently completes setup but fails login. Loose email validation at line 83 has the same mismatch risk; the reviewer's email example was initially unexecuted and was subsequently confirmed by the parent.
3. **P1 — Baseline retains ambient schema routing.** Rounds 6/7 require explicit targeting without routing alterations or ambient fallback. Baseline omits options; pinned pg inherits PGOPTIONS. Parent confirmed staging receives six committed managed tables before public verification fails. Enforce the effective schema before DDL and verify inside the transaction.
4. **P2 — Logout failure is hidden.** T03 requires logout. SecurityClient ignores returned errors and redirects even on exception. A transient failure can leave the session valid. Source-confirmed by the reviewer; subsequent browser fault proof is parent's evidence.

The reviewer found no additional scope creep. A pre-password-change pending challenge survives rotation in the parent probe, but the precise existing requirement says revoke “other sessions,” without explicitly covering unfinished challenges. That observation is a policy proposal below, not mislabeled as a failed explicit acceptance criterion. Server-only provider backup-code viewing/TOTP generation are not exposed HTTP disclosure paths; MFA re-enable rejects an already verified factor, and unconfigured OTP delivery rejects. Those investigated candidates are not reported as vulnerabilities.
