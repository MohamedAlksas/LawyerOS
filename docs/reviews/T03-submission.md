## Behavior delivered

1. **Closed First-Owner Provisioning**:
   - Public self-registration is completely disabled in Better Auth.
   - Interactive CLI (`npm run auth:provision-owner`) provisions the initial `OWNER` account.
   - Enforces single-use bootstrapping: once an owner exists in the database, `hasAnyOwner()` permanently blocks further provisioning attempts.
   - Passwords must meet complexity requirements (minimum 10 characters, mixed case, numbers, symbols).

2. **Session Lifecycle Enforcement**:
   - 30-minute sliding inactivity expiration: sessions inactive for 30 minutes are immediately expired on the server.
   - 12-hour maximum session lifetime: sessions older than 12 hours cannot be extended and require complete re-login.
   - Database-backed sessions stored in PostgreSQL `Session` table.
   - Active session tracking: records IP address, user agent, last active timestamp, and expiration time.

3. **Two-Factor Authentication (TOTP) & Emergency Recovery Codes**:
   - RFC 6238 TOTP enrollment and verification using Better Auth `twoFactor` plugin.
   - AES-256-GCM symmetric encryption for TOTP secrets and recovery codes using `BETTER_AUTH_SECRET`. No plaintext secrets stored in PostgreSQL.
   - Single-use emergency recovery codes: once used, a recovery code is marked as spent and rejected upon replay.
   - QR code generation and secret display for authenticator app setup in `/settings/security`.

4. **Server-Side Session Revocation**:
   - Users can view all active sessions with device/browser breakdown in `/settings/security`.
   - Single session revocation: immediately invalidates a specific session in the database.
   - Bulk session revocation: "Revoke all other sessions" terminates all sessions except the current active session.

5. **Narrow Shared Authorization Boundary**:
   - `requireActor(headers)`: server-side helper validating incoming request session, resolving the `User` and `Session`, and returning a strongly-typed `Actor` context (`id`, `email`, `role`, `sessionId`).
   - `authorize(actor, allowedRoles)`: role-based guard enforcing least privilege (`OWNER` vs `MAINTAINER`), preventing maintenance-role or unauthenticated access to protected domains.
   - Sanitized authentication error messages preventing username or account enumeration.

6. **Arabic RTL Operational Screens**:
   - S01 Login (`/login`): clean Arabic RTL layout with username/password fields, sanitized error alerts, and automatic redirection to `/verify` when 2FA is required.
   - 2FA Verification (`/verify`): dual-mode verification supporting 6-digit TOTP codes or emergency recovery codes.
   - S14 Security Settings (`/settings/security`): view and manage active sessions, enable/disable TOTP 2FA, generate backup recovery codes, and review security status.

## Security/privacy effects

- **Encrypted TOTP Storage**: `twoFactor` table stores TOTP secret and backup recovery codes symmetrically encrypted via AES-256-GCM. Compromise of database dump does not disclose TOTP seeds.
- **Anti-Enumeration**: `/login` returns generic Arabic error `بيانات الدخول غير صحيحة` (Invalid credentials) for both non-existent users and bad passwords, preventing account enumeration.
- **Session Lifecycle Boundaries**: Stale sessions cannot be resurrected; sliding inactivity timeout of 30 minutes and absolute maximum lifetime of 12 hours are enforced server-side.
- **Strict Actor Derivation**: Client-supplied user IDs or role headers are ignored; actor context is derived exclusively from the verified server-side session token.

---

## Rollback / recovery notes

- **Schema Rollback**: Drop auth tables (`DROP TABLE IF EXISTS "twoFactor", "verification", "account", "session", "user" CASCADE; DROP TYPE IF EXISTS "UserRole";`).
- **Secret Rotation**: `BETTER_AUTH_SECRET` can be rotated via scheduled re-encryption of `twoFactor` secret fields if necessary.
- **Emergency Access**: If the primary owner loses their authenticator and recovery codes, the CLI tool or direct administrative database intervention can reset the `twoFactor` record for that specific user ID without affecting core office records.
